# Результати Code Review та Рефакторингу

## 1. Список виявлених Code Smells / Проблем

В наданому фрагменті legacy-коду виявлено такі критичні недоліки:

1. **Неінформативні та абревіатурні назви (Bad Naming / Cryptic Names):**
   Назви функції (`process`) та змінних (`d`, `r`, `i`) абсолютно не відображають їхнього бізнес-сенсу. Це ускладнює читання коду іншими розробниками (доводиться вчитуватися в логіку, щоб зрозуміти, що `d` — це масив користувачів, а `r` — результат).
   
2. **Застарілий синтаксис (Legacy Syntax - `var`):**
   Використання ключового слова `var` для оголошення змінних є застарілою практикою (до ES6). `var` має функціональну область видимості та піддається "hoisting" (підняттю), що може призвести до важковловлюваних багів. Сучасний стандарт вимагає використання `const` та `let` з блочною областю видимості.

3. **Імперативний цикл замість декларативних методів (Imperative Loop):**
   Використання класичного циклу `for (var i = 0; ...)` перевантажує код технічними деталями (керування індексами, інкременти, ручне наповнення масиву через `push`). Для масивів у JavaScript вже давно існують вбудовані декларативні методи, які роблять код читабельнішим.

4. **"Піраміда умов" або надлишкова вкладеність (Arrow Anti-pattern / Deep Nesting):**
   Два послідовні блоки `if` (`if (d[i].active == true)` та всередині `if (d[i].age > 18)`) створюють зайву вкладеність. Їх можна легко об'єднати за допомогою логічного оператора `&&` або винести в окремий етап фільтрації.

5. **Нестроге порівняння та надлишкова логіка (Loose Comparison & Redundant Logic):**
   Вираз `d[i].active == true` використовує нестроге порівняння (`==`), що є небезпечним через неявне приведення типів у JS. Крім того, перевірка булевого значення на рівність `true` є надлишковою — достатньо написати просто `if (d[i].active)`.

6. **Конкатенація рядків замість шаблонних рядків:**
   Вираз `d[i].name + " - " + d[i].age` використовує старий синтаксис конкатенації. Шаблонні рядки ES6 (Template Literals) є набагато сучаснішими та зручнішими.

## 2. Відрефакторений код (Clean Code ES6+)

Ось чиста, декларативна та сучасна версія функції без зміни її початкової логіки:

```javascript
/**
 * Фільтрує активних повнолітніх користувачів та повертає масив їхніх даних у форматі рядків.
 * @param {Array} users - Масив об'єктів користувачів.
 * @returns {string[]} Масив рядків виду "Ім'я - Вік".
 */
function getActiveAdultUserLabels(users) {
    if (!Array.isArray(users)) return [];

    return users
        .filter(user => user.active === true && user.age > 18)
        .map(user => `${user.name} - ${user.age}`);
}

module.exports = getActiveAdultUserLabels;
```

*Примітка щодо логіки:* Оскільки в оригінальному коді використовувалося порівняння `== true`, у відрефактореному варіанті застосовано строге порівняння `=== true` для безпеки типів. Якщо вхідні дані гарантовано містять суто булеві значення, умову у `filter` можна скоротити до: `user => user.active && user.age > 18`.
